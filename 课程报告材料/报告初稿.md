## 1 需求分析

### 1.1 问题提出

在以合同或订单为业务依据的经营活动中，企业通常需要记录客户资料、合同金额、分期应收安排和实际到账信息。若应收计划与到账记录分散在表格中，容易出现客户信息重复、逾期金额难以追踪、部分回款无法准确分配到应收款、汇总统计口径不一致等问题。

本系统面向承担客户和财务数据维护工作的业务人员，提供客户、合同、应收款和回款信息的集中管理。系统重点记录实际到账与应收款之间的核销关系，使用户能够查询每笔应收的已收金额、未收余额和到期状态，并汇总客户及日期维度的回款情况。系统规模定位为课程综合实验，不替代企业完整财务软件。

### 1.2 系统分析

系统主要参与者为业务/财务操作人员。操作人员维护客户、合同和应收计划，登记到账回款，并将回款核销到相关应收款；系统校验客户归属和金额边界，保存数据并提供余额与汇总查询。

核心业务实体包括客户、合同、应收款、回款和核销明细。一个客户可关联多份合同；一份合同可包含多笔应收款；一笔回款可核销多笔应收款，一笔应收款也可由多笔回款结清。回款尚未分配的部分作为未分配回款单独统计，不直接视为任何应收款已结清。

**数据流说明：** 用户输入业务资料 → 服务端校验 → 数据库存储 → 应收余额/回款汇总查询 → 页面展示。写入失败时返回业务错误，回款和核销明细作为一个事务提交或整体回滚。

### 1.3 功能需求

| 模块 | 主要功能 | 主要输入/输出 |
| --- | --- | --- |
| 客户管理 | 新增、查询、编辑、启用/停用客户 | 客户基本资料、客户列表与详情 |
| 合同管理 | 维护合同并关联客户 | 合同编号、客户、金额、日期、状态 |
| 应收款管理 | 按合同创建应收计划，查询余额和状态 | 应收金额、到期日、已核销额、未收余额 |
| 回款管理 | 登记、查询实际到账 | 客户、日期、金额、方式、流水号 |
| 回款核销 | 将到账金额分配到一笔或多笔应收款 | 回款 ID、应收款 ID、核销金额 |

### 1.4 非功能性需求

- **数据正确性：** 金额使用定点小数类型；服务端校验金额为正、回款归属一致、核销额不超过回款可分配金额或应收余额。
- **一致性：** 新增回款及其核销明细在数据库事务内完成，失败时整体回滚。
- **可维护性：** 采用前后端分离的 REST API；客户、合同、应收、回款和统计模块职责清晰。
- **易用性：** 页面提供关键字、日期区间和状态筛选，对业务校验错误显示可理解的信息。
- **安全性：** 当前课程版本范围为受控环境下的单用户或简化登录；若实现认证，应记录实际方式和权限边界。
- **可恢复性：** 提供数据库备份及恢复步骤，并在恢复后验证关键业务数据。

## 2 数据库设计与实现

### 2.1 概念设计

系统概念模型由客户、合同、应收款、回款和核销明细构成。核销明细用于表达回款与应收款的多对多分配关系，并记录每次分配金额。该模型保留“实际收款”与“应收款结清”两个业务事实的区别。

【待补：依据最终 DDL 核验 ER 图及实体属性，见 `图稿/ER图.mmd`。】

### 2.2 逻辑设计与物理设计

规划关系模式如下，最终以代码仓库中的实际 DDL 为准：

- 客户（客户ID，客户编号，客户名称，联系人，电话，邮箱，地址，状态，创建时间）
- 合同（合同ID，合同编号，客户ID，合同名称，签订日期，合同金额，状态，备注）
- 应收款（应收款ID，应收编号，合同ID，应收金额，到期日，说明，创建时间）
- 回款（回款ID，回款编号，客户ID，到账日期，回款金额，回款方式，流水号，状态，备注）
- 核销明细（明细ID，回款ID，应收款ID，核销金额，创建时间）

每张表设置主键；合同外键引用客户，应收款外键引用合同，回款外键引用客户，核销明细分别引用回款和应收款。客户编号、合同编号、应收编号、回款编号及适用的流水号应按业务要求设置唯一约束。金额字段使用 `DECIMAL(12,2)`，Java 侧使用 `BigDecimal`。最终索引按常用客户、日期、状态和外键查询条件确定。

关系模式以实体和联系拆分，避免将客户、合同、回款及多个核销对象重复塞入同一记录；核销金额保存在联系实体中，保持每次分配事实可追踪。最终范式分析需结合实际字段函数依赖检查，并说明为查询汇总保留或建立的视图/索引。

## 3 应用程序设计

### 3.1 系统功能设计

应用按客户、合同、应收款、回款、核销、统计等模块组织。前端通过统一 REST API 与 Spring Boot 服务通信；服务层负责业务规则和事务控制，持久层负责访问 MySQL。客户、合同和应收款由成员 A 实现，回款、核销和统计由成员 B 实现，前端由 AI 辅助生成并由两位成员共同验收。

【待补：实际功能结构图、页面截图、模块调用关系。】

### 3.2 系统详细设计

回款登记关键流程：接收回款及可选核销明细 → 校验客户和金额 → 校验应收款归属与剩余余额 → 在事务中保存回款及核销明细 → 返回更新后的应收余额；任一校验或写入失败时回滚事务。应收款余额按应收金额减去有效核销明细之和计算；未分配回款为回款金额减去该回款的有效核销金额之和。
